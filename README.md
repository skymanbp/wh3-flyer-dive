# Flyer Dive & Take-off — Total War: WARHAMMER III mod

Steam Workshop: <https://steamcommunity.com/sharedfiles/filedetails/?id=3840651516>
(pack `ld_air_dive.pack`)

## What it does

* **Physics dive.** A flying unit that dives onto the ground keeps its speed
  when it lands, and only the bodies it actually hits slow it down. This is
  done with code caves in the game's battle code, installed through
  memreader Plus (site table `mod/script/campaign/lore_disasters/data/ld_flyer_dive_site.lua`,
  generated by `mod/tools/pipelines/dive_cave_asm.py`).
* **Take-off from melee.** A flyer engaged in melee can take off again; it is
  held on the ground only while more than half of its living models are being
  struck (site table `ld_flyer_takeoff_site.lua`, generated by
  `mod/tools/pipelines/pin_cave_asm.py`).
* **Flight animation tables.** The vanilla flight tables are shipped under new
  names (`<name>_ld_dive`) with the landing hand-off changed, registered and
  repointed through DB rows, plus flyer entity rows (charge speed per flyer,
  charge distances, deceleration, turning), two locomotion rows and the
  collision attack (`mod/tools/lib/air_dive_rules.py` is the single source of
  these rules).
* Works in single player, in multiplayer campaign battles when every player
  runs the same version (memreader Plus agreement), and in multiplayer custom /
  quick battles (the game's own mod checksum keeps both sides on one version).

**Prerequisite:** [memreader Plus](https://steamcommunity.com/sharedfiles/filedetails/?id=3811098873)
(Workshop 3811098873). Without it the rule scripts log "not installed" and the
game runs as vanilla for those two rules.

## Balance submod (optional)

A second pack, `flyer_dive_balance.pack`, carries the two balance changes that
used to be in the main pack (user ruling 2026-11-17, `docs/DECISIONS.md` D1):

* **Breath attacks while engaged.** Breath abilities can be used while the
  flyer is engaged in melee and while it is on the ground (the game's own
  usage-flag table, shipped whole under its vanilla path minus those rows).
* **Mass cut.** Large flyers weigh ×0.85, very large ones ×0.75. The celestial
  lion and The Wise One (the boss lion) are cut as large; the game's nine flying
  war machine and chariot bodies (thunderbarges, sky-junk, sky lantern,
  skycutters, burning chariot, gyrocopter, gyrobomber) keep their mass
  (`MASS_CUT_MACHINES` also names two Lore Disasters bodies this pack never ships).

It **requires the main mod** and is built by the same run (below), so the two
packs always match: its flyer rows are the main pack's rows with only the mass
changed, and both packs carry the same build stamp. When they come from
different builds, the battle log `ld_flyer_dive.txt` gets a
`BALANCE MISMATCH` line. Load order needs no manual step: a project measurement
(Lore Disasters ledger, RESIST-W2) found that the row from the pack whose name
sorts first wins, and both the submod's pack name and every one of its table
fragment names sort before the main pack's, so it holds whichever of the two
names the game goes by (a swap test with these two packs is still to be run).

## Repository layout

Script paths and file names inside the pack (`script/campaign/lore_disasters/...`,
`ld_flyer_*`, `ld_air_dive.pack`) are the names the published mod ships under; they stay
as they are so subscribers' load order and the multiplayer agreement keep working.

| path | what |
|---|---|
| `mod/assets/air_dive/` | renamed flight tables (`.bin`, animpack) and `air_dive_manifest.json` (sha256 of each) |
| `mod/script/...ld_flyer_*.lua`, `lib/ld_cave_common.lua` | battle and campaign entry scripts, rule modules, generated site tables |
| `mod/assets/vendored_scripts/memreader_plus/` | memreader Plus 0_15_2 (MIT, see its `third_party_licenses.txt`), read by the cave-site tests; the pack does **not** include it, it is a declared prerequisite |
| `mod/tools/pipelines/` | `build_air_dive_minimod.py` (builds the pack), `air_dive.py` (derives the tables), cave assemblers, probes and the automated battle test |
| `mod/tools/lib/`, `mod/tools/tests/` | rule module, animation codecs, tests |
| `mod/tools/lib/flyer_db.py`, `mod/tools/data/flyer_db_schemas.json` | DB table reader/writer and the recorded writer schemas (self-contained build) |
| `mod/tools/data/main_mod_flyers.json`, `mod/tools/lib/main_mod_flyers.py` | a recorded snapshot of the Lore Disasters mod's donor flyers and their riders, input for the future main-mod adapter pack; `air_dive.py` counts them when it derives the tables |

## Building the pack

The build is self-contained (since 2026-11-17): it needs only this repository,
the installed game and a few PyPI packages (`lz4`, `zstandard`, `pefile`).
It reads the installed game (`db.pack`, `local_en.pack`, `Warhammer3.exe`) every
time, so a game patch is a re-run.

```
cd mod
python -P tools/pipelines/build_air_dive_minimod.py --out <path>/ld_air_dive.pack --balance-out <path>/flyer_dive_balance.pack
```

One run writes both packs (the names are fixed: the build refuses others).

Set `LD_WH3_DATA` to your game's `data` folder if it is not the default path in
the script. The DB tables are written by `mod/tools/lib/flyer_db.py` (the table
reader/writer, copied from the Lore Disasters mod) with the writer schemas
recorded in `mod/tools/data/flyer_db_schemas.json`; every installed table the
build reads must still re-encode byte-identical, so a patched table is refused,
not guessed. Rebuilding the cave site tables and their emulator checks also
needs `keystone-engine` and `unicorn`
(`python tools/pipelines/dive_cave_asm.py --write-site`). The automated battle
test (`tools/pipelines/air_dive_autotest.py`) needs `psutil`; its optional
`--entity-read` reader is not part of this repository.

Re-deriving the staged flight tables (`python -P tools/pipelines/air_dive.py`,
only when the rules or the game's tables change; `--check` compares a fresh
derivation with the staged files) reads the installed game and the snapshot
`mod/tools/data/main_mod_flyers.json` (the Lore Disasters mod's donor flyers and
riders, taken 2026-11-17), nothing else.

## Development home

Since 2026-11-17 this repository is where the flyer mod is developed (user
ruling). It builds, re-derives and tests on its own and reads no other
checkout; the Lore Disasters mod no longer carries the flyer mod. Its flying
bodies and donor flyers are kept here as recorded data (the snapshot above and
the rows marked as adapter input in `mod/tools/lib/air_dive_rules.py`) for a
separate main-mod adapter pack.

# 飞兽俯冲与近战起飞（全面战争：战锤 3 模组）

创意工坊：<https://steamcommunity.com/sharedfiles/filedetails/?id=3840651516>（包 `ld_air_dive.pack`）

## 做了什么

* **物理俯冲**：飞兽俯冲落地后保持速度，只有真正撞到的兵才把它减速。做法是经
  memreader Plus 在战斗代码里装代码洞（位点表由 `dive_cave_asm.py` 生成）。
* **近战起飞**：接战中的飞兽可以再起飞；只有现存模型过半正在挨打时才被按在地上
  （位点表由 `pin_cave_asm.py` 生成）。
* **飞行动作表**：原版飞行动作表改名（`<名>_ld_dive`）发货、改落地交接，经数据表登记
  并改指；另有飞兽实体（逐个飞兽的冲锋速度、冲锋距离、减速、转向）、两行移动常数与冲撞攻击
  （规则唯一源 `mod/tools/lib/air_dive_rules.py`）。
* 单机可用；联机战役各端版本一致时可用（memreader Plus 协商）；联机自定义 / 快速战斗
  可用（游戏自己的模组校验保证两端同一版本）。

**前置模组**：memreader Plus（创意工坊 3811098873）。没装时两条规则不生效、按原版运行。

## 平衡子模组（可选）

第二个包 `flyer_dive_balance.pack` 装着原来在主包里的两项平衡调整（用户 2026-11-17 裁定，
`docs/DECISIONS.md` D1）：

* **陷入近战时可用吹息**：吹息类技能在陷入近战时、已落地时都能释放（游戏自己的技能可用条件表，
  按原版路径整表发货，只去掉这几行）。
* **质量下调**：大型飞兽质量 ×0.85，超大型 ×0.75。昊天狮与「智者」按大型算；游戏里九种飞行战争机器
  与战车的实体（雷霆空艇、天舟、天灯、斩天者、浴焰战车、矮人直升机、矮人轰炸机）质量不变。

它**需要主模组**，并且和主包由同一次建包生成（见下），两包始终一致：它的飞兽行就是主包的行、
只改了质量，两包带同一个建包戳；来自不同建包时，战斗日志 `ld_flyer_dive.txt` 会写一行
`BALANCE MISMATCH`。加载顺序不用手动调：本项目此前实测（主模组台账 RESIST-W2）是名字排序在前的
包的行生效，子模组的包名和每个表片段名都排在主包之前，所以不论游戏看的是哪个名字都成立
（这两个包的对调实测还没做）。

## 建包

建包命令一次写出两个包（`--out <路径>/ld_air_dive.pack --balance-out <路径>/flyer_dive_balance.pack`，
包名固定，别的名字会被拒绝）。自 2026-11-17 起建包只需要本仓库、安装的游戏和几个 PyPI 包（`lz4`、`zstandard`、
`pefile`），命令见上面英文部分。数据表由 `mod/tools/lib/flyer_db.py`（从主模组照搬的
表读写器）按 `mod/tools/data/flyer_db_schemas.json` 里记录的表结构写出；建包读到的
每张原版表仍须逐字节往返，游戏更新改了表就拒绝而不是猜。重生代码洞位点表与模拟器检查
另需 `keystone-engine` 与 `unicorn`；自动实机测试需要 `psutil`。

## 开发位置

用户 2026-11-17 裁定：飞兽模组从此在本仓库开发，主模组不再包含它。本仓库自己建包、重生动作表、
跑测试，不读任何别的仓库。主模组的飞行实体与捐赠方飞兽作为记录数据留在这里
（`mod/tools/data/main_mod_flyers.json` 快照与 `air_dive_rules.py` 里标明「适配包输入」的几组行），
留给将来单独的主模组适配包用。
