W1–W16、冲撞攻击、喷吐、起飞、K 方案是一批一批加上去的，各管一段。本节把它们收成**一份规格**：两根支柱、谁管什么、数在哪、现有改动的去留、往下怎么做。今后任何飞兽改动先对照本节；数一律只在 `tools/lib/air_dive_rules.py`（动作参数在 `pipelines/air_dive_clips.py`，由同一处的规则派生）。

**总原则（§C8-61 用户裁定）**：冲多深、穿不穿、撞多重，**由计算得出，不事先按兵种定**。飞兽触地时不清零速度、不放减速的动作，带着落地速度往前走，只被它撞上的身体减速（碰撞物理）；质量、速度与引擎自己的碰撞算法（含拒马质量倍数，那也是算出来的）决定结果。不写按目标兵种的深度表，不按兵种设深度上限，不做隐藏被动。

**支柱一 · 动作：一次连贯的俯冲冲阵。**

1. 一个动作看起来是一次：空中接近 → 斜线下降 → 以接近的速度触地 → 冲进敌阵 → 被撞停或接战。不许「刹一下再猛冲」：落地前不刹车（飞兽减速度 30）。
2. 动作只管样子，不管冲多深、何时停。现在落地后的位移全由 489 号冲阵动作的根骨带（W8 实证：落地后速度被清零，只有 484 / 489 攻击槽的根骨会移动实体），这是过渡做法（K：从落地速度起步只减不加）；引擎路线做成后，触地不再清零，冲阵改由移动本身带着走，减速的冲阵动作撤掉，动作只给样子（落地后的奔跑 / 冲撞姿态）。
3. 覆盖全部飞兽，不只冲阵：发货飞兽用到的 50 张飞行动作表里 35 张没有 484 号移动攻击（32 张只有 489 扑击，3 张两者都没有：`dr1b_chaos_dragon`、`dr1b_chaos_dragon_boss`、`dr1b_wyrm_dragon`；清单见 §C11），接触攻击只能是扑击或站定招，动作重做要按骨架给它们补 484（AIR-DIVE-RELEASE-W1 已补齐：全用 CA 自己的同骨架动作，见上「每张飞兽表都有 484 移动攻击」）。起飞和降落不直上直下（W1 实测：起飞爬升高于落地下降，差额在动作开始前垂直掉完），追敌时不悬停在目标头顶不打。这两项还没查根因，先查后做（步骤 4）。
4. 骑兵类别的飞兽（飞马骑士等）引擎从不放 489（只放 484），K 的冲阵动作对它们不起作用：A / K / 原版三种包里飞马都停在第一排（中位 ±1 米）。不改兵种类别（类别连着冲锋加成、反骑兵等一串原版规则）；引擎路线让它们落地后也按地面冲锋走，就一并解决。

**支柱二 · 机制：落地后由碰撞物理算出结果。**

1. 原版地面骑兵就是这样停的（§C11 AIR-DIVE-CONTINUOUS-W1 cav_* 四局，逐骑分析）：圣杯骑士（质量 1200）、阿尔道夫狮鹫骑兵（1500）以 10.6–11.2 米/秒撞上，在 0.6–0.8 秒内由约 11 降到 0.5 米/秒，最大减速度中位 18–27 米/秒²（p90 约 33），远超马自己能刹的 7 / 5.8；期望速度（兵模 +0x1c8）接触后 1 秒仍读 10.0–10.7。每一骑都是**先停、后接战**：停下比命令换成接战早 0.4–0.8 秒（中位，12 组）。所以停下来的是前面的身体（碰撞），不是接战锁定；接战是停下之后才进入的状态。这批局里原版骑兵对大剑士、站定长矛、戟兵、混沌勇士、帝国骑士都没冲穿（中位进阵 0.4–5.3 米），对阵深 22–29 米的民兵进 9–13 米——这是那组质量与速度算出来的结果，不是规则；更重、更快的冲锋者由同一套算法算出更深。
2. 已静态查清的原版规则（Warhammer3.exe 9.0.5，只读），都是计算不是兵种表：站定的兵按身后排数与来向得一个质量倍数，有 `charge_defense` 或 `charge_defense_vs_large` 属性的再 ×2，封顶 10，质量 × 倍数 ≥ 600 就标成「小个子推不动」；冲锋者撞上拒马会被反弹一刀，按撞击速度对 10.5 / 7 / 4 米/秒三道门槛各 50% 被掀飞 / 撞倒 / 撞退，低于门槛 75% 撞退；两两碰撞时按一个整数分层分推开量（层差 0 / 1 / 2 / 3 / 4 时高层的那个只吃 1.0 / 0.8 / 0.2 / 0.1 / 0），分层存在兵模 +0xc，它装的是不是体型档还没核实。
3. 现状（过渡做法）不符合本原则：落地后的冲阵由动作根骨带，几乎不看目标。星龙对剑士、大剑士、站定长矛都以原速穿过；蝎尾狮对长矛只慢约 2 米/秒；狮鹫骑士 4 骑里 2 骑停在第一排（落地离敌太近，冲阵不触发）、2 骑穿过 18–20 米。
4. **做法（引擎路线，§C8-61 定）**：落地的飞兽在命令上已是地面冲锋者——兵模 +0x330 的命令对象落地时不换，原版骑兵冲锋拿的正是同一个（虚表 0x143ade800），撞上后逐骑换成接战（0x143ade470）。缺的只是移动。运行时探针（`--entity-dump`，§C11）查清了「清零」的真相：没有一条把速度写成 0 的指令，而是触地那一刻引擎给飞兽**开了一个动作**——兵模 +0x26c 的状态由 30（按移动走，冲锋飞行与地面奔跑都是它）变成 55（动作驱动：这段时间实体的速度就是动作根骨的速度），+0x278 的槽位换成落地槽（原版 104，根骨不施加，所以站住；我方 489，冲阵动作带着走），+0x898 指向这个动作、+0x27c 从 0 数拍，动作放完才离开 55。地面冲锋者（巨人对照局）冲进敌阵时一直留在 30，放的移动攻击（484 / 485）叠在移动上，撞停才变 33。代码：0x143089284 开动作（写 +0x898、+0x278、+0x27c，60 多处调用），0x14308fa70 每拍推进动作（0x14308fc1b 写 55）。要做的：找到触地时开这个动作的那一处调用，让落地的冲锋者留在 30，原版移动与碰撞就接手。写内存补丁照起飞那套：memreader Plus 位点加载器、联机各端同一个包同一份位点才装（§C8-57 / §C8-58 先例），有网络防护的风险。
5. 数据层路线都不合本原则，不再做：R（放开受击打断，让拒马反弹截停）实测无效，冲阵动作不被反弹打断；M（按飞兽自身动量定冲多远）是事先定的行程，不由碰撞算出。
6. 伤害：引擎自带的冲撞攻击（W16 B 档：飞兽武器的 `collision_attack_max_targets`）保留，它本身按速度与撞到的人数结算。冲锋时自动开的隐藏被动（D 档）不做（§C8-61：不做隐藏被动）。

**步骤**

1. 运行时探针（进行中）：现行 K 触地放的 489 是近战出招分派（0x1432597a0）在冲锋撞上时挑的接触攻击；只改数据去掉 104 与强制跳击（原型 G）后，有移动攻击的狮鹫骑士留在移动状态、结果开始随目标变（民兵全穿、站定戟兵与长矛挡住一半），星龙则在挑招时被清零移动、转成站定出招（状态 33）。测试补丁（出招分派 0x1432597fa 处对飞兽改走开动作 0x143089284 那条路）实测：星龙对民兵冲进 16 米穿过，对站定的戟兵与长矛被原版拒马反弹截停、弹回 4 米——结果已由目标是否站定算出；但落地后仍放一个动作、移动由动作根骨带。再让出招分派对仍在高速移动的落地飞兽不出招（测试洞 `td_skip`）：它确实留在移动状态 30，但按自己的减速度在落地点刹停——飞行冲锋的移动目标就是落地那一点，没有伸进敌阵的目标。再在测试里把冲锋目标（实体 +0x1e0 / +0x1e8，另三份拷贝 +0x194、+0x7f8、+0x838）每拍改到敌阵里 20 米：触地那一拍读到伸进去的目标时，星龙留在移动状态、以 11–15 米/秒冲穿站定的戟兵与长矛、一路冲撞，只被碰撞减慢 3–4 米/秒；读到引擎改回的前沿目标时就在原地清零——触地「清零」即「落地时已到冲锋目标」。找到了设目标的那一处：冲锋目标选择函数（0x143096e20 起）按实体 +0x104（飞兽在空中为 2）与冲锋命令标志 +0xc4 第 2 位（单体怪物的冲锋本来就带，巨人也一样）选「前沿接触点」，否则选「穿阵」：目标位置 + 方向 × 引擎自己算的距离——原版骑兵就是这一支，目标在后排之后 16–37 米、靠碰撞停下。测试洞 `td_through` 让飞兽走穿阵一支：目标落在敌阵后面、不再被改回，星龙对戟兵两局冲穿 15.9 / 27.0 米；另外两道仍在落地那一拍被出招分派选成站定出招而清零。落地那一拍放过站定出招的根因是测试洞看错了速度：那一拍两个标量速度已读 0、速度向量还是 15 米/秒，紧接着还有一拍过渡状态 33；改为看水平速度向量、状态 30 或 33 后，星龙三道都不出招、只被碰撞减慢（民兵进 23 米、站定长矛 3.9 米、站定戟兵在前沿被撞停）。「硬落地」查清了：落地那一拍的降落处理调停飞包装 0x14308b420，把飞行模式写 0、交给地面移动，地面移动按自己的减速度刹停；测试洞 `td_keep` 让仍在高速移动的落地飞兽不停飞，星龙与蝎尾狮因此带着速度冲进敌阵、由碰撞减慢；剩一处直接重新寻路（0x14307b4b0）没拦住，部分局仍在落地后约 0.3 秒刹住（§C11 第 8 步）。
2. 按探针结果做引擎补丁：落地不清零，交给原版移动与碰撞；位点经 memreader Plus 加载器、联机协商；报改动量与风险。（进行中：分支 air-dive-mp-dive-w1 把 `td_through`、`td_skip`、`td_keep` 三个洞的发货部分做成正式补丁，见 §C11 AIR-DIVE-MP-DIVE-W1。）
3. 测试包 A/B：同一飞兽对轻步兵、重步兵、站定拒马、骑兵，看结果是否随质量与速度变；撤掉 489 冲阵动作与跳击 100 后复核。
4. 支柱一普查：全部飞兽骨架的 102 / 103 / 104 / 105 / 484 / 489 槽、起降的竖直剖面；用探针查「悬停不打」的根因。
5. 做起降斜线动作与落地后的冲撞姿态动作。
6. 之后 K 的减速度、引擎补丁、动作一起接进 `air_dive_rules`，小模组与主包同走这一处发货。
